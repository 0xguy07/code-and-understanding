# GIT For Beginners
## Local and Remote Repositories

### Local Repository

When creating a **project** you can create it locally, somewhere like `Documents`. For example: 

- /Documents
    - /Project
    
When you use the `CLI` and move into the `Project` folder, you can run `git init` to initialize the folder which will ensure you can use `git` on the files within this directory, and ensure they're in version control, using git. 

Git can be used locally, without needing a remote repository, such as Github. 

### Remote Repository

A remote repository can be BitBucket, or Github or Gitlab. Github is the remote VCS software which I am most familiar with.

When you have completed some work locally, you can commit the code, and push it to the remote repository. The benefits of a remote repository: 

1. Collaboration
    - You can work on, and maintain code with other people on a team, or on a hobby project. 
    - When working on a team, someone can review your code, via a Pull Request before merging it into the rest of the code base, and can provide feedback. 
2. Backup
    - Instead of relying on code being local on a machine, you can be sure that your code will be safe on a remote repository. 
3. Exposure
    - If you are pushing your code to a remote repository, you can get recognition for the work you are doing.
